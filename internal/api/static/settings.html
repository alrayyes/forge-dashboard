      GitHub

      A token sees every repo it can push to, private included. Leave the token blank to keep the one already saved.

      Needs read-only access to your repos, their issues, pull requests, and commit status, plus read/write access to each repo's webhooks — to show whether one's already pointed at this dashboard, and to create or fix one up when you click "Add a webhook" (see the Webhooks page). Create a token with that scope already set → Classic tokens: the repo scope (or just public_repo if every repo you track is public) already covers this. Fine-grained tokens: grant Metadata, Issues, Pull requests, Commit statuses, and Checks, each set to Read-only, plus Webhooks set to Read and write — and make sure the repo is actually in this token's own repository list (or that it's set to "All repositories"), separately from those permissions. A repo left out of that list fails with "Resource not accessible by personal access token" even though every permission above is granted correctly, and that's easy to hit for a repo created after the token, or a token deliberately scoped to a subset of repos.

      Shows that account's public repos, unauthenticated — no credential involved.

      Forgejo

      Same trade-off as GitHub: a token sees private repos, a username alone sees public ones only.

      Required if you set a token or username below — otherwise Forgejo is skipped entirely, with nothing to tell it which instance to use.

      Needs your repos and their issues/pull requests, plus each repo's webhooks — to show whether one's already pointed at this dashboard, and to create or fix one up when you click "Add a webhook" (see the Webhooks page) — select the write:repository and read:issue scopes. Forgejo's webhook API has no separate read-only scope, so even just checking coverage needs write:repository. Open your instance's token settings → (fill in the instance URL above first)

      Webhooks

      Add these to a repo to update your dashboard the moment something happens there, instead of waiting on the next poll. Optional — polling every 30 seconds keeps running either way. Full setup steps →

      Repo → Settings → Webhooks → Add webhook. Content type application/json, secret below, events: Pull requests, Issues, Statuses, Check runs.

      Repo → Settings → Webhooks → Add Webhook → Forgejo. Secret below, trigger on: Pull Request, Issue, Push, Status.

      The same secret goes in both webhooks above — it's what proves a delivery actually came from your forge.
