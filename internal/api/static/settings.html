      GitHub

      A token sees every repo it can push to, private included. Leave the token blank to keep the one already saved.

      Needs read-only access to your repos, their issues, pull requests, and commit status — nothing else. Create a token with that scope already set → Classic tokens: the repo scope (or just public_repo if every repo you track is public). Fine-grained tokens: grant Metadata, Issues, Pull requests, Commit statuses, and Checks, each set to Read-only.

      Shows that account's public repos, unauthenticated — no credential involved.

      Forgejo

      Same trade-off as GitHub: a token sees private repos, a username alone sees public ones only.

      Required if you set a token or username below — otherwise Forgejo is skipped entirely, with nothing to tell it which instance to use.

      Needs read-only access to your repos and their issues/pull requests — select the read:repository and read:issue scopes. Open your instance's token settings → (fill in the instance URL above first)

      Webhooks

      Add these to a repo to update your dashboard the moment something happens there, instead of waiting on the next poll. Optional — polling every 30 seconds keeps running either way. Full setup steps →

      Repo → Settings → Webhooks → Add webhook. Content type application/json, secret below, events: Pull requests, Issues, Statuses, Check runs.

      Repo → Settings → Webhooks → Add Webhook → Forgejo. Secret below, trigger on: Pull Request, Issue, Push, Status.

      The same secret goes in both webhooks above — it's what proves a delivery actually came from your forge.
